What to build next — in strict order

Fix immediately (breaks current value)
The biggest gap right now is that your frontend graph tab and timeline tab have no rendering components. You have the data — the backend builds timeline, network_graph, and platform_summary — but the React side doesn't visualise them. This means your best output is invisible. Build the vis-network graph component and the Recharts scatter timeline first, because everything you've already built starts showing results the moment these land.
High priority connectors you're missing
Three connectors will dramatically improve result quality with zero cost. The crt.sh connector is the most impactful — it reveals subdomains, associated emails, and org history from TLS certificates for any domain pivot, completely free. The Wayback Machine CDX connector surfaces deleted profiles and historical data. The Google Dork auto-generator multiplies the value of your existing web search connector by generating 10+ targeted query variants instead of one plain search.
Your Reddit data is also sitting unused as OSINT pivot data. You already have it ingested — writing a connector that searches your existing MongoDB posts/comments by author field takes under 50 lines and immediately gives you rich social thread history.
Identity resolution gaps
The two missing pieces here are the name-to-username variant generator and the email-to-username pivot. Without these, a query of "Arjun Sharma" only searches the literal string — it never tries arjun.sharma, arjuns, arjunsh on platforms. These two additions multiply your username enumeration coverage by 5–8x for name and email inputs.
Image pipeline — all missing
The entire image module is unbuilt. The Flask upload endpoint, InsightFace wiring, EXIF extractor, SauceNAO connector, and React upload UI are all zero. Since this is your biggest differentiator (no standard OSINT tool does this as a first-class query mode), treat it as one sprint — build all five pieces together because they're tightly coupled.
PDF export and watchlist
PDF is a one-afternoon job — your template from the previous prompt is ready, WeasyPrint is installable, you just need the Flask endpoint wired. Do this before any demos. The watchlist system uses APScheduler which you already have — it's essentially just scheduling run_full_investigation for saved session queries and diffing new evidence against stored evidence.
New additions worth prioritising
Phone number intelligence (free numverify tier) and the email header parser are both high-signal, low-effort additions. The Shodan free tier (100 queries/month) adds significant power for domain and IP pivots. The LLM-powered narrative synthesis — one Claude API call reading all evidence — turns your template summary into something that reads like a real analyst wrote it, which is the difference between a prototype and a product.
What to skip for now
Neo4j migration, writing style fingerprinting, crypto address tracing, and content similarity clustering are all later priority. Your MongoDB-based graph data is sufficient for MVP. Add Neo4j only when you're doing cross-session queries at scale.
